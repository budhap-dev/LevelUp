# LevelUp Engineer

A knowledge base and interview-prep app for senior engineers and architects moving towards Staff, Principal, Architect and Engineering Manager roles.

Content lives in Markdown under [`content/`](content/). A build-time pipeline checks and compiles it into JSON, which the React app loads one topic at a time.

## Getting started

Requires Node.js 22+.

```bash
npm install
npm run dev        # http://localhost:5173 — recompiles content on save
```

| Script | What it does |
|---|---|
| `npm run dev` | Dev server; content errors show in the terminal and browser overlay |
| `npm run content` | Compile and validate `content/` → `src/generated/` (lists every error and warning) |
| `npm run build` | Content + type-check + production build into `dist/` |
| `npm test` | Unit and component tests (Vitest) |
| `npm run typecheck` | Content + `tsc -b` |
| `npm run notes -- <command>` | Manage Notes from the terminal (see [Notes](#notes)) |

## Project structure

```
api/                     Notes API: one Vercel Function (router.ts) + _lib/
content/                 Topic Markdown, groups.json, paths.json, glossary.json, _template.md
docs/prompts/            Prompt for generating topic content
scripts/content/         Build-time pipeline: parse, validate, render to JSON (+ tests)
scripts/notes/           Notes CLI, dev-server API middleware, API tests
scripts/pwa/             Decides which build chunks the service worker precaches
src/
  app/                   Router, layout, sidebar, error pages
  components/            Shared UI (badges, prose, theme toggle)
  features/              One folder per feature (dashboard, catalogue, topic, …)
  lib/content/           Content schema (shared with the pipeline) and loaders
  generated/             Pipeline output (gitignored)
```

## Adding or updating a topic

1. Every topic already has a stub at `content/<group>/<id>.md`. To add a brand-new one, copy [`content/_template.md`](content/_template.md); the file name must equal `id` and the folder must equal `group`.
2. Write the content by hand or generate it with [`docs/prompts/generate-topic.md`](docs/prompts/generate-topic.md).
3. Run `npm run content` and fix what it reports.

**Guided:** `npm run topic` (or `npm run topic -- caching`) does all of this for you. It suggests the next topics, copies a ready-made prompt to your clipboard, takes the model's reply from the clipboard, checks it, sends fix requests back, protects existing question ids, then previews, tests and opens the PR.

**Statuses:**
- `stub`: no content; shown as "coming soon".
- `draft`: missing pieces are warnings.
- `complete`: missing pieces are errors, and the question mix (4 Foundation / 6 Senior / 5 Architect) is checked.

**The format rules the pipeline enforces:**
- The nine `##` section headings from the template, and no others.
- Interview questions as `### Question? {#stable-id}` with **Level**, **Model answer**, **What the interviewer is looking for**, **Follow-ups** and **Red flags** fields. The `{#id}` keys review history, so keep it when you reword a question.
- Cheat-sheet bullets as `- **Front** — back`. Each one becomes a flashcard.
- Diagrams as ```` ```mermaid ```` code blocks.
- Plain Markdown only. Raw HTML is stripped, and `.mdx` files are rejected.
- `related` topic ids and every topic in `paths.json` must exist.

Put `VERIFY:` in front of any claim that still needs checking. The topic page shows how many remain.

## Finding things

- **Search:** press <kbd>Ctrl</kbd>/<kbd>⌘</kbd>+<kbd>K</kbd> or <kbd>/</kbd>, or use the header button. Results cover topics, sections and sub-headings, interview questions and cheat-sheet cards, grouped by type and ordered by best match. Choosing a question opens it on its topic page. The index is generated by the content pipeline (`src/generated/search.json`), and both it and Fuse.js load only when search is first opened.
- **Catalogue filters:** level, group, tag and "with content only". They're kept in the URL (`/topics?level=Architect&tag=kafka`), so filtered views can be bookmarked. Tags on topic pages link straight to a filtered view.
- **Topic navigation:** an "On this page" list that tracks your scroll position on wide screens, or a row of section chips on narrower ones. Each section heading has a `#` link for sharing.

## Your progress

- **Per topic:** set Learning, Learned or Needs revision. Topics you open with content are marked Learning automatically, and the section you were reading is remembered for "continue where you left off" on the dashboard. Your status shows in the sidebar and catalogue, and you can filter the catalogue by it.
- **Bookmarks:** bookmark a whole topic, or an individual interview question from its expanded answer. They're all listed on `/bookmarks`.
- **Topic notes:** private per-topic notes at the end of each topic page, stored in this browser. These are different from the standalone [Notes](#notes) section. They save as you type, and anything pending is saved if you leave the page.
- **Backup:** `/settings` exports everything as JSON and imports it again. You see a preview first, then choose Merge (the newest entry wins) or Replace. There's also a confirmed reset.

Progress lives in the browser (`localStorage`, key `levelup:progress`) and stays in sync across tabs. The code is in [`src/lib/progress/`](src/lib/progress/):

- `ProgressStore` is a small async backend interface, so an API can replace localStorage without UI changes.
- `ProgressController` holds state in memory, updates the screen instantly and saves in the background (debounced, with a reported save status).
- `normalise.ts` validates, migrates and merges data. It's hand-written rather than Zod, to keep the app bundle small.

## Practice: Interview mode and Flashcards

- **Interview mode (`/interview`):** choose topics, levels and a session size, then for each question think it through (a timer runs), reveal the model answer, and rate yourself **Again / Hard / Good / Easy**. Keys: <kbd>Space</kbd> reveals, <kbd>1</kbd>–<kbd>4</kbd> rate. Each button shows when the question would come back. "Again" brings the card back a few cards later in the same session.
- **Flashcards (`/flashcards`):** the cheat-sheet cards, which flip to show the answer and use the same ratings and schedule.
- **Session order:** due cards first (most overdue first), then new cards at random. "Practise ahead" also includes cards that aren't due yet. Due counts appear in the sidebar and on the dashboard.
- **Scheduling ([`src/lib/srs/sm2.ts`](src/lib/srs/sm2.ts)):** SM-2, where Again/Hard/Good/Easy map to quality 1/3/4/5. Easiness starts at 2.5 and never drops below 1.3. Passing intervals go 1 day → 6 days → previous interval × easiness. Again resets the card to 10 minutes. On top of SM-2, Hard grows the interval by ×1.2 and Easy adds a ×1.3 bonus (4 days for a new card), as in Anki.

## Learning paths

`/paths` lists the career routes defined in [`content/paths.json`](content/paths.json), such as Senior → Staff/Principal and Senior → Solution Architect. Each path page shows its topics in order, with your status on each one. It highlights the next required step, and a Start/Continue button opens that topic. A step counts as done when you mark its topic **Learned**. Optional steps (`"optional": true`) are shown but don't count towards completion. The dashboard shows each path's progress and its next step.

To add or change a path, edit `paths.json`: `id`, `title`, `description` and `steps` (`topicId`, plus an optional `note` and `optional`). The content pipeline rejects unknown topic ids.

## Content summary and glossary

`/summary` shows how complete the knowledge base is. It covers overall progress (topics, questions against the 15-per-topic target, flashcards, study time, VERIFY markers), questions by level, learning-path coverage, and a per-module table. Each topic's row shows its status, question count and level mix, flashcards, sections present and unverified claims. The page is built from the content manifest, so it updates automatically whenever content changes.

`/glossary` lists key terms with a definition, key details, use cases and links to the topics that cover them. You can filter by text or module and jump to a letter. Ctrl/⌘ K search includes glossary terms, and a result opens `/glossary#<id>`.

To add a term, append an entry to [`content/glossary.json`](content/glossary.json). Each entry needs `id` (kebab-case), `term`, `aka` (alternative names), `group`, `definition`, `details`, `useCases` and `related` (topic ids). Wrap code in `backticks`. The content pipeline validates the schema, rejects duplicate ids and terms, and checks that every group and related topic exists.

## Notes

`/notes` is a personal notebook, **separate from the topics**. Use it for anything: interview prep, meeting notes, ideas, links. There are three ways to add a note:

- **In the app:** use the **Note** button in the top bar, or the **+** in the sidebar's Notes menu. Your notes are listed on the Notes page, not in the sidebar.
- **Ask Claude:** for example, "add a note titled *Kafka questions* with …". Claude runs the CLI below.
- **From the terminal:** use the CLI yourself.

Each note has a title, rich text (headings, lists, checklists, quotes, code, links), diagrams and file attachments of up to 4 MB each. To attach a file, use **Attach**, drop it on the note, or paste it in. Notes save as you type. Search covers titles and bodies, finds partial words ("cach" → "caching") and highlights the matches.

Notes can hold two kinds of diagram, both added from the editor toolbar:

- **Mermaid:** a code block written in [Mermaid](https://mermaid.js.org/intro/syntax-reference.html) syntax, drawn as a diagram in the app's theme. Use **Edit code** to change it; the preview updates as you type. A ```` ```mermaid ```` fence in Markdown from the CLI becomes one of these, so Claude can add diagrams too. The Mermaid source is searchable.
- **draw.io:** a hand-drawn diagram made in the [diagrams.net](https://www.drawio.com) editor, which opens full-screen inside the app. Save & Exit stores the diagram in the note as an SVG with the draw.io drawing embedded, so **Edit diagram** reopens it fully editable. The editor runs in your browser, loaded from diagrams.net, and needs a connection. Nothing is uploaded to diagrams.net. draw.io diagrams count towards a note's 4 MB size limit.

```bash
npm run notes -- add --title "Kafka questions" --body "- [ ] ISR vs acks=all" [--attach diagram.png]
npm run notes -- add --title "Retro" --file retro.md   # Markdown file
npm run notes -- list [search words]
npm run notes -- show <id>
npm run notes -- append <id> --body "More **Markdown**"
npm run notes -- attach <id> file.pdf other.png
npm run notes -- delete <id>...
npm run notes -- migrate                                # create/upgrade tables
```

How it works:

- **Storage:** notes live in **Neon Postgres**, created through the Vercel Marketplace and connected to the Vercel project. Attachments are stored in the database too (`bytea`). Search uses a generated `tsvector` column.
- **API:** [`api/router.ts`](api/router.ts) handles every `/api/*` request on Vercel. `npm run dev` serves the same handler through a Vite middleware.
- **Locking:** notes are locked behind a passphrase. A browser stays unlocked for 30 days, using a signed HttpOnly cookie. The rest of the site stays public.
- **Environment variables:**
  - `DATABASE_URL` is set by the Neon integration.
  - `NOTES_PASSWORD` is the passphrase.
  - `NOTES_SESSION_SECRET` is a random string. Change it to sign every device out.

  Run `npx vercel env pull .env.local` to get them locally.
- **Offline:** notes need a connection; they aren't cached offline.

## Themes and motion

- **Themes:** seven solid-colour themes (Daylight, Midnight, Sepia, Rose, Forest, Ocean, High contrast) plus System, which follows the OS light/dark setting. Colours live only in [`src/styles/themes.css`](src/styles/themes.css), as tokens such as `--canvas`, `--fg`, `--accent` and `--muted`, and are used through Tailwind classes such as `bg-canvas`, `text-muted` and `bg-accent`. To add a theme, add a block there and an entry in [`src/lib/themes.ts`](src/lib/themes.ts). [`scripts/checks/themes-contrast.test.ts`](scripts/checks/themes-contrast.test.ts) fails if any theme misses WCAG AA contrast.
- **Motion:** page transitions, a circular reveal when switching themes (View Transitions API), an animated sidebar accordion, a slide-out mobile drawer with swipe-to-close, and diagrams that animate in (nodes fade in, edges draw). Everything respects `prefers-reduced-motion`.
- **Logo:** [`src/components/Logo.tsx`](src/components/Logo.tsx) uses the active theme's accent colour. [`public/favicon.svg`](public/favicon.svg) has the same geometry in the default indigo.

## Performance

The dashboard ships in the main bundle. Every other page is a lazily loaded route chunk (`lazy` in [`src/app/router.tsx`](src/app/router.tsx)), as are each topic's JSON, the search index with Fuse.js, and Mermaid.

## Offline and install (PWA)

LevelUp is an installable Progressive Web App. Use the browser's **Install** button, or **Add to Home Screen** on iOS. It works offline after the first visit.

- **What's available offline:** the service worker (Workbox, via [`vite-plugin-pwa`](https://vite-pwa-org.netlify.app/)) precaches the app shell, every page and every topic, about 1.4 MB. Progress, notes and reviews are already stored on the device, so Interview mode and Flashcards work offline too.
- **Diagrams:** Mermaid and its diagram chunks (about 6 MB) are *not* precached. They are cached the first time a diagram renders. A diagram you haven't seen before shows its source while you're offline and renders when the connection returns. [`scripts/pwa/precache-scope.ts`](scripts/pwa/precache-scope.ts) makes this split by walking the chunk graph from the entry and stopping at Mermaid.
- **Updates:** when a new version is deployed, a toast offers **Reload**. Choosing **Later** keeps the current version until the next visit. Open tabs check for updates hourly and whenever the tab regains focus. The sidebar footer shows the running version — the build date (e.g. `v2026.11.24`) plus the commit — and keeps a **Reload** button while an update is waiting. Deploy with `npm run deploy`, which passes the commit to Vercel's build. While the browser is offline, an **Offline** badge appears in the header.
- **Icons:** [`public/`](public/) holds `pwa-192x192.png`, `pwa-512x512.png`, `maskable-512x512.png` and `apple-touch-icon.png`, rendered from the favicon's geometry. If you change the logo, regenerate them.
- **Trying it locally:** the service worker is only built in production, so run `npm run build && npm run preview`.

## Deployment

[`.github/workflows/ci-deploy.yml`](.github/workflows/ci-deploy.yml) runs `npm ci`, `npm test` and `npm run build` on every push to `main` and every PR, then uploads `dist/` to Azure Static Web Apps. Each PR gets its own preview URL, which is removed when the PR closes.

One-time setup:

1. In the Azure portal, create a **Static Web App** (Free plan). For **Deployment source** choose **Other**, so Azure doesn't add its own workflow.
2. Copy its **deployment token** (Overview → Manage deployment token).
3. In GitHub, go to Settings → Secrets and variables → Actions and add it as `AZURE_STATIC_WEB_APPS_API_TOKEN`.

Until that secret exists, the workflow still runs the tests and build and skips the deploy steps. [`public/staticwebapp.config.json`](public/staticwebapp.config.json) sends deep links (such as `/topics/caching`) to `index.html`, caches hashed assets for a year and never caches `index.html`, `sw.js` or the web manifest, so updates are picked up straight away.
